# Model team

This page describes the agent harness of this project for people. Agents do not need to read it.

| Role | File or setting | Model | Effort |
| --- | --- | --- | --- |
| orchestrator | `model` in `.claude/settings.json` | opus | xhigh |
| verifier | `.claude/agents/verifier.md` | opus | high |
| acceptor | `.claude/agents/acceptor.md` | opus | high |

## Subagent model

A subagent that has no model of its own uses the helper model. An Agent tool call with a `model` parameter overrides it.

## Outage

`fallbackModel` replaces the main model only when it is overloaded or not available.

## Precedence

This project file has priority over the user settings. The options `--model`, `--effort` and `--advisor`, and a resumed session, have priority over this project file.

## Reload

Claude Code reloads `advisorModel`, `fallbackModel`, `env` and the `.claude/agents` directory while it runs. Claude Code reads `model` and `modelSettings` only when a session starts.

## Skills

spec-dna writes these stage skills: `spec-dna-brainstorm`, `spec-dna-specify`, `spec-dna-clarify`, `spec-dna-write-plan`, `spec-dna-tdd`, `spec-dna-review`, `spec-dna-finish`. Each skill runs spec-dna commands for one stage of a change. spec-dna writes these event skills: `spec-dna-post-mortem`. A failure or an incident starts an event skill, and it has no stage.

## Review policy

`REVIEW.md` holds the review policy of the Code Review service. The local review command does not read it. The skill `spec-dna-review` has the same text.

## Subagent card

The hook `subagent-card` gives each subagent this card when it starts. The agent file and the brief of the subagent have priority over it. The agent `acceptor` gets another line 3: commit only `acceptance.toml`, and do not push.

```text
Subagent card. Your agent file and your brief have priority over this card.
1. Do only the task of the brief. Change only the files of `Files`. If the task needs more, stop and report it.
2. Read the brief, then the files that it names. Run `spec-dna context <file>` before an edit. Search only for a fact that these do not give.
3. Do not commit, push or change the git state.
4. Report the result, the changed files, each command that you ran with its result, and the open issues.
5. For a rule that the project files do not state, add `Lessons:` before the last line, with one line for each: `- Target: <file>. Text: <sentence>. Evidence: <what happened>.`
6. End the report with one line: `State: COMPLETE`, `State: COMPLETE_WITH_CONCERNS`, `State: NEEDS_CONTEXT` or `State: BLOCKED`.
```

## Hooks

`context-meter` tells an agent the size of its context once at each level. `fanout-cap` asks the person before a workflow whose agent count can exceed the cap. `protect-tests` asks the person before an edit of a test file that git tracks. It asks on a branch that starts with `fix/`. `subagent-card` gives each subagent the card above when it starts. `return-state` asks a subagent once for the last line `State: <state>` when its report has none. `fix-limit` tells an agent to stop after 3 failed fixes of one shell command. Each teammate needs spec-dna 0.8.1 or later on `PATH`. Without it, the hooks do nothing.

## Check after a restart

1. Read the header. It shows the main model.
2. Type `@`. The list shows the agents.
3. Run `/tasks`. It lists the running agents.
4. Run `/usage`. It shows the cost of each model.

Generated by spec-dna. Change `[harness]` in `spec-dna.toml` and run `spec-dna init --reconfigure`.
