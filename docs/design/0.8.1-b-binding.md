# Design of spec-dna 0.8.1, part B: the holes of the bind

This page designs items 2 to 7 of part B of 0.8.1. They close the holes of the bind of a `covers:` tag that part A left open (B2, B3 and B4 of [part A](0.8.1-a-evidence-and-context.md#amendment-of-the-build-2026-11-24)), and they test the bind on reports that real runners wrote. The change `bind-holes` builds it. [Test reports](../test-report.md#the-rule-of-a-bind) holds the rule of the bind for users. This page gives the changes and their reasons. The sections use the numbers of the items of the owner, because the design of part B on another page uses the next D numbers.

## 1. Items 3 and 4: the identity of a case

**Problem**:

- B2: the step "another file" of the rule reads a `classname` of one word as a file of the code tree. It then leaves the own case out of the set, also when that case failed. A passed weak case of the same name then proves the tag (E2e). The same class of fault gives E2c and E2d in the row of Go.
- B3: a failed case of another language with the name of the test stays in the set as a weak link when its `classname` names no file of the code tree. It then fails a tag whose own case passed (E2f).
- E2a and E2b: the built name of a call misses 2 forms that the runners write. The own case then leaves the set by its name.

**The invariant**:

A failed case never proves a requirement, in any profile. Precisely: when a runner wrote a case for the test under the tag, and that case failed or was skipped, the proof of the tag is not passed.

The rule keeps it by construction. A case leaves the set of a tag only by a verdict of the closed list below. Each verdict reads a field that the report holds, and no documented shape of a runner writes that field so for the test under the tag. Each other case that names the test is an own case or a weak link, and the worst of them decides.

**The identity of a case**:

The identity of a case is its locator and its head. The head is the name without the row tail and the prefix of a Playwright project. The locator is the first field of this table that the case has. The identity takes the `file` and the `classname` of the test case itself, and the `classname` is the suite of the case. spec-dna does not read the `name` of the `testsuite` element (answer of the owner of 2026-11-27). nextest, Go and Surefire write the same text there as the `classname`, and jest-junit writes a title or `undefined`.

| The case has | The locator | Kind |
| --- | --- | --- |
| a `file` | the path of `file` | full |
| a `classname` with a `/` and a `.` in its last segment, or with the extension of a script | the path | full |
| a `classname` with `::` | the binary id of nextest | full |
| a `classname` with a `/` and no extension | a folder path: a Go import path, or a folder of gotestsum `relative` | full |
| a `classname` of 2 or more segments joined by `.`, with no space | a dotted name: a module of pytest, a class of the JVM or .NET | full, except a title reading of a call (rule 4) |
| a `classname` of one word, or `.` | a word | relative |
| a `classname` with a space, or equal to the name | none: it is a title | none |
| no `classname`, or an empty one (the reader reads an empty `classname` as none): the line format, and jest-junit or Vitest with a template for a test outside a group | the path of the line, or none for `-` | full, or none |

**The rule** (changes against the rule of part A):

1. Another file (B3). A case with a full locator is another test when no reading of the locator names the tag file. This applies to a pair that no row lists too. It applies only where the scanner holds the value of the tag side of each reading in full. It does not apply where the row of the tag ties the case by the built identity, as in part A (`ties`): the rows of nextest and Go, where only the fields of the row decide (rules 2 and 3), and a JVM or .NET tag whose class chain the scanner cannot read, or whose class chain ends the `classname` of the case. There the case stays weak when the fields of the row do not decide. Part A also needed the locator to name another file of the code tree. That condition goes. Thus a dotted `classname` of another language is another test also when no folder shows its package, and a path of a file outside the code tree is another test. A locator names the tag file when:
    - a path equals the path of the tag file, or one ends the other at a `/`;
    - the stem of a `::` binary id is the stem of the tag file, or the folder of a `main.rs`;
    - the folder of the tag file ends a folder path, or the import path of that folder equals it;
    - a dotted name relates to the dotted path of the tag file (one ends the other at a `.`), or equals the package or namespace with the class chain of the tag file.
2. A word (B2, E2c, E2d). A `classname` of one word, and `.`, never make a case another test by rule 1. A word names a folder, a module or a package below a root that the report does not give, a class of the default namespace, or a title. In the row of the tag, a word ties the case (`Same`) only when a reading of the row names the tag file and the readings of the word name one file or folder of the code tree. It makes the case another test (`Differs`) only when no reading of the row names the tag file. Each other word is `Unread`, so the case is weak. The readings:
    - Go: the folder below the module root (`relative`), and the last segment of the import path (`short`), for the root package too, where it is the last segment of the module path. A module path of one word is the import path of the root package. `.` is the root of each module of the code tree, so 2 `go.mod` files make it not unique.
    - pytest: the stem of the module, below any rootdir.
    - cargo-nextest: the package.
    - JVM and .NET: a class of the default namespace.
    - A call: a title (rule 4).
3. The full fields of the row of the tag stay decisive: the dotted path and the class chain of pytest, the package and the binary of nextest, the import path of Go, the full class name of the JVM and .NET with a `package` or `namespace` line, and the path of Vitest and Playwright. The full name of a row that holds it stays decisive too, with the forms of rule 4.
4. The name of a call (E2a, E2b). The built heads of the rows of a call get 2 forms that the runners write with their defaults:
    - With no group around the test, the title after one space. jest-junit joins an empty `classname` and the title with a space.
    - In the row of the defaults of jest-junit (a `classname` that is no path), the joins with ` > ` and ` › ` too, as in the row with `file`.

    The title readings of a call are the chain of groups joined with each of the 3 joins, the first title of the chain, the title of the test, and the full title. A `classname` that equals a title reading of the test under the tag is a title. Rules 1 and 2 never make such a case another test. The reader of the report trims no name, so `case:` still equals the name byte for byte, and a name with a space before it does not become a weak link of a tag of another form.
5. The other steps of the rule of part A stay: the lookup, the row, the classification, the uniqueness with the readings of rule 2, the repeats, `case:` and the worst of the set.

**Why the invariant holds**:

These are the only verdicts that leave a case out of the set of a tag:

- (a) its name does not name the test, by the closed list of the name forms;
- (b) its `file` names another file;
- (c) no reading of its full locator names the tag file, where the scanner holds each reading in full and the row does not tie the case (rule 1);
- (d) a full field of the row of the tag differs under each reading of the row (rules 2 and 3);
- (e) the row holds the full name, and the head of the case is no built head (rule 4).

For each documented shape, a runner writes the case of the test under the tag with the name forms, the `file` of the tag file, a locator that names the tag file, the fields of the row, and a built head. Thus none of (a) to (e) leaves such a case out. The worst of the set sees its fail or skip. The tests check this on each real report and on each cell of the matrix (assertion A2): when the own case failed or was skipped, the proof is not passed.

The limits that stay are the shapes that no row documents: a `titleTemplate` of jest-junit that drops the groups (`jest/reports/title-only.xml` keeps `no-case`, limit 10), and a `classNameTemplate` such as `{displayName}` that gives no title reading. A setting of this kind changes the name or the field of the case, so the case does not name the test in the forms of the rule.

**What becomes weaker, and what becomes stronger**:

The table is a prediction against the 220 binds of E2 (each report alone). The tests of section 5 assert it, so a difference stops the build.

| Report | Tag | 475d8a8 | After |
| --- | --- | --- | --- |

| `go/relative.xml` | `solo/solo_test.go` `solo-alarms` | failed, no SD621 (the case of another module) | failed, SD621 `not-unique`. Weaker, and no longer a silent misattribution |

- `classname-describe.xml` with `src/Gate.js`: the 5 tags keep the results of the report with no such file (E2e is closed).
- The 3 reports of `namesake/` with no `py/test_gate.py`: the 2 Rust tags read passed with no SD621, and the jest tag reads failed with SD621 (E2f is closed).

What can turn from proven to unproven in other projects:

- A case of a runner that no row lists, whose full locator names no reading of the tag file. In part A it was a weak link that could prove (passed with SD621). Now it is another test, so with no other case the tag gets `no-case`. An example is a Rust test that a converter writes with a dotted `classname`. The way out is `case:`, which stays weak.
- A word that part A read as the tag file with no count of its readings: gotestsum `relative` and `short` when 2 Go modules share `.` or the name of a folder, and a pytest module with one stem in 2 rootdirs. These binds were silent, and they now give SD621 `not-unique`.

**Codes**:

No new code, reason, cause, key or JSON field. The `fit` of a bind that a word ties is `classname`.

**Upgrade**:

No key. A current corpus passes `check` with no edit. The results of `check --reports` change as the table above says.

**Cost**:

Rule 1 removes a lookup. Rule 2 counts the module roots of Go once in each run, from the list of the paths of the code tree, and it reads each `go.mod` once, as today. Rule 4 adds at most 5 heads for each tag. No byte in a request of an agent.

**Does not prove**:

That a runner of another version writes the same shapes. The script `generate.sh` writes the reports again with each version that it names.

## 2. Item 5: many tags on one title

**Problem**:

A tag reads each case whose name has a segment or the last word of the title of the test. For the title `renders`, that is each case `W<i> > renders` of each other file. Then the work is the number of tags times the number of such cases: 171 s for 2,000 tags on 600,000 cases. Most of these cases are another test by their file or by their full name, so the tag reads them for no gain.

**The target**:

2,000 tags above tests with one title, and 600,000 cases of that title in other files. `check --reports --all` takes at most 1 s more than the same load with no tag. This is the target that the bench checks, because the time with no tag is the read of the report, which this change does not touch. The total is less than 2 s for each load whose time with no tag is less than 1 s. The measure is the median of 5 runs, with a release build, on a machine with a load average below 2. The peak RSS is at most 1.25 times the peak RSS of the load with no tag. The 3 loads:

- L8: Vitest, the `classname` is the path of one of 1,000 other files.
- L9: jest-junit defaults, the `classname` equals the name.
- L10: the line format, with the path `-`.

**The algorithm**:

1. The shape class of a case: the facts of the case that the row reads (a `classname`, a `file`, a `classname` equal to the name, a `::`, a `/`, the extension of a script, a `.` in the last segment, and the characters of a package name). The row of a case is a function of the form of the tag and the shape class.
2. The binder keeps 2 maps, both split by the shape class. The head map holds the head of each name and, for a name with `::` or `/`, each prefix at a `::` or `/`. The segment map holds each whole segment of the head and the last word of the name. Each case is in one shape class, so the maps hold no more entries than today.
3. A tag reads the head map with each built head of each row. It reads the segment map only for the shape classes whose row, for the form of the tag, has no full name: the line format, a pair that no row lists, and a row whose heads are empty because the identity is not built. Each other case with a segment of the title and no built head is another test by verdict (e), so the result is the same.
4. A case that the tag reads in the segment map and that has a `file` or a path as its `classname`: the tag reads only the cases whose path has the base name of the tag file, where rule 1 applies to the row of the case. Rule 1 makes each other such case another test. The tag reads each other case with a locator, as today.
5. A case that the tag reads in the segment map and that has no locator (no `file`, and no `classname` or a title): its judgment does not depend on the tag file. It depends on the name of the test, the form, the flags of a call and of a name in backticks, and the receiver with its suite functions. The binder judges these cases once for each such signature. It keeps their list and a summary for the worst of the set: the first failed case, the first skipped case, the passes of each identity, and the counts. A tag merges the summary with its other cases. The cause of each weak link (`by-name` or `no-identity`) comes from the identity of the tag.

Thus the work of a tag is in proportion to its built heads and to the cases of its set that have a locator. The first tag of a signature also judges the cases with no locator, one time. The work does not grow with the cases of another full name or another file.

**The bench**:

`bench/tool/bind.py` writes the loads L8, L9 and L10 with 600,000 cases and 0, 500 and 2,000 tags, with made-up names. For each load it runs `spec-dna evidence stamp`, then `check --reports --all` 5 times after one warm-up, with `wait4`, as `bench/tool/run.py` does. It writes `bench/results/tool-bind.json`: for each load and count of tags, the median wall time, the peak RSS, the load average before and after the runs, and whether the target holds. CI does not run it, because a shared runner has no stable time.

**The guard in `cargo test`**:

No guard reads a clock.

- A count of the judgments (the counter `calls::JUDGE` of `cfg(test)`): L8 and L9 with 60,000 cases and 200 tags judge at most 2 cases for each tag. L10 with 60,000 cases and 200 tags judges at most 60,000 + 2 × 200 cases.
- The same result: a reference binder of `cfg(test)` judges each case of the wide union of 475d8a8, with the rule of section 1. It gives the same `Proof` and `Bind` as the binder (the fields `cases`, `shared`, `case`, `fit`, `why`, `reason` and `near`, and the passes), on each cell of the matrix, on each report of `tests/fixtures/runners/`, and on L8 to L10 with 60,000 cases.
- The clock bounds:
  - `src/evidence.rs:7170`, the matrix (1.0 s): it goes. The matrix asserts at most 4 judgments for each bind.
  - `:6047`, a long name (2 s): it goes. The test asserts the count of the keys of the name, which is the cost that the cap of part A bounds.
  - `:6283`, 300 files (2 s): it goes. The test asserts at most 2 judgments for each tag.
  - `:6300` runs only with `--ignored`, so it stays.
  - `tests/evidence_reports.rs:3355` guards a stall of 65 to 73 s through a process: its bound goes from 10 s to 30 s, as the other bounds of a process in the tests.

**Codes**: none. **Upgrade**: none. **Cost**: the memory of the maps does not grow. The summary of a signature holds 4 numbers and 2 names.

**Does not prove**: a time on another machine. The bench gives the machine and its load.

## 3. Item 6: the notes of the acceptor

1. **A template in a nested group is not a twin.** Today a template counts as a twin only when its chain equals the chain of the tag (`build_twins`, `theirs(*line).is_none_or(|c| &c == mine)`). A template in a nested group, such as `it.each(['opens'])('%s')` in `describe('cold')` below `describe('Valves')`, can give the full title `Valves cold opens` of the test `it.skip('cold opens')` of `describe('Valves')`. With only the case of the template in the report, the tag reads passed, fit `file`, with no SD621. The fix: a template of the file is a twin when a full title that it can give equals a full title of the tag. Its full title is its chain and its literal, joined with each join of the rows of a call, where each placeholder reads as any text. This replaces "a template of the same chain whose literal can give the title". A template in a sibling group whose full title cannot give the title stays no twin. The test (it fails at 475d8a8): the cell of the acceptor gives passed with SD621 `not-unique`. A cell with the template in `describe('hot')` stays silent.
2. **D89 item 3 is stale.** The text of [D89](0.8.1-a-lifecycle-and-harness.md#d89-the-hook-that-runs-the-tests-also-stamps-the-reports-item-7) gives the first rule of the scan: a word of the `id:` or the `entry:`. The build reads the `entry:` only, with a list of commands, the goals of the build tools and the flags that skip the tests. The fix is a dated note below D89 that names the rule of [init](../init.md#a-hook-that-runs-the-tests). This page adds it. The fix is text, so no test fails first.
3. **A second `case:` is lost.** `# covers: req#r3 case:test_x case:test_y` binds `test_x`, and nothing tells of `test_y`. The quoted form with a second `case:"c"` is not valid. The fix: a second `case:` word before the next `covers:` of the line makes the `case:` not valid. The tag then binds no case (reason `no-case`), and the message of a `case:` that is not valid names the cause: one tag takes one `case:`, so write one tag for each case. The test (it fails at 475d8a8): the tag with 2 words and a passed case `test_x` reads unbound, and the quoted form stays not valid (guard). A tag with `case:` and a second `covers:` with its own `case:` on the same line binds both (guard).
4. **The class index does not read `struct` and `enum`.** A twin that declares the full class name as a `struct` (C#, also `record struct`, `readonly struct` and `ref struct`) or as an `enum` (Java and C#) gives a silent bind (limit 15). The fix: the index reads the words `struct` and `enum` as declarations, in the same way as `class`. In Kotlin, `enum class` is already a `class`. The test (it fails at 475d8a8): a C# file with `struct ValveTest` and a Java file with `enum ValveTest` in the namespace of the tag make the bind weak, with SD621 `not-unique`.

**Codes**: none. Note 3 adds a cause to the text of a `case:` that is not valid. **Upgrade**: none. **Cost**: note 1 compares the templates of the file with the full titles of the tag (at most 3 titles for each template). Note 4 adds 2 words to the scan of the index.

## 4. Item 7: the level of SD621 in `strict`

**Decision of the owner** (item 7): a weak bind (SD621) is an error in `strict` only where a documented reporter setting gives a strong bind. Docs give that setting for each tested runner. Elsewhere SD621 is a warning.

**The rule**:

1. spec-dna knows the row and the cause of each weak case of the set. It reads them from the report and the tag file, with no other input. A weak case is fixable by a setting when it is weak only by its locator, the identity of the test is built and unique, and a documented setting gives the case a full locator. With the setting, such a case is an own case or another test, and no longer weak. The fixable pairs are a closed list:

    | The weak case | Its runner | The setting that gives a strong bind |
    | --- | --- | --- |
    | The row of the defaults of jest-junit (a call, a `classname` that is no path, no `file`), cause `by-name` | jest-junit; Vitest with a `classnameTemplate` | jest-junit: `addFileAttribute: "true"`, or `classNameTemplate: "{filepath}"`. Vitest: the default `classname` |
    | The row of Go with a word or `.` (rule 2 of section 1), cause `by-name`, or `not-unique` by the readings of the word only | gotestsum `relative` or `short` | gotestsum: the default `--junitfile-testcase-classname=full` |

    Each other weak case has no such setting: the cause `no-identity`, `not-unique` by the code (a twin, an overload, a template, 2 files), the line format, a pair that no row lists, nextest with no `Cargo.toml` or with a module in both root files, Go with no `go.mod`, and pytest, whose default is strong.
2. In `strict`, with no rule for SD621 or for the group `reports` (in the root or in `[rules]`), SD621 is an error when each weak case of the set of the tag is fixable, and a warning in each other case.
